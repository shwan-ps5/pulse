# AGENTS.md: how Pulse works (for AI assistants extending it)

Pulse = Beat Saber-style rhythm game, PS5 (jailbroken) + PS VR2 + Sense controllers. Any MP3 -> analysed on console -> 4 note maps.
Native C++17, OpenGL 4.6 via ps5-opengl (Mesa) on console, SDL2 on desktop. Title ID PPSA99993. License GPL-3.0-or-later.
Code comments in this repo are written for you, not for humans: dense, contract-style. Read headers first, then the function.

## comment notation
pre/post/inv = precondition/postcondition/invariant. U: units. CS: coordinate space. T: threading. `!` = hazard (burned before).
`->` returns. `ref:` related code. `W:` why. `kX` constants. `=>` implies. `~` approx.

## commands
- desktop game: `make play` (or `./build/game [--songs DIR] [--diff easy|medium|hard|extreme] [--bot] [--screen title|select|options|help|help2|results] [--shot SECONDS out.ppm] [song.mp3 map.pulse]`)
- tests: `make test` (core rules, ranks, mapper validity). must pass before any push. add a CHECK when you change a rule.
- map tool: `make build/pulse-map && ./build/pulse-map song.mp3 -o dir`; viewer: `make view`.
- console dev build: `bash ps5/build.sh` -> `build/ps5/dist/PPSA99993` (+ live log to the PC via tools/logsrv.py, UDP 9023).
- shareable build: `bash ps5/release.sh` -> `build/ps5/dist/Pulse-<ver>.zip` (demo song, no log address, NO network code).
- python: use `.venv` (numpy, pillow, cairosvg). tools: makeart.py, makedemo.py, bakefont.py, make-index.py.
- NEVER push to a console, run it remotely or upload payloads without the user's explicit go each time (they said so).
  push = FTP of `build/ps5/dist/PPSA99993/*` except `assets/songs/**` to `ftp://<console>:2121/mnt/usb0/PPSA99993/` (game must be closed).

## repo map (one line each; every file has a header comment with details)
- core/game.{h,cpp}: rules engine (Session): cut detection, scoring, combo, energy, events. platform-free. core/bot.h: scripted player for tests.
- analysis/analysis.cpp: samples -> bpm, beats, bars, sections. analysis/mapper.cpp: Result -> 4 maps, cues, .pulse io, validate().
- audio/mp3.cpp: minimp3 decode + resample to 48 kHz stereo int16 while decoding.
- game/main.cpp: the app (state, screens, input, loop). game/library.cpp: scan songs, cache maps. game/scores.cpp: bests + ranks.
  game/tags.cpp: ID3 titles + cover art + name tidying.
- render/render.{h,cpp}: all drawing (notes, sabers, text, panels, background, bloom, hint). render/fontatlas.h generated by tools/bakefont.py.
- platform/platform.h: window/pad/audio/log abstraction; platform_ps5.cpp (EGL, scePad, sceAudioOut) and platform_sdl.cpp (desktop).
  platform/vr.h: headset+controllers API; vr_ps5.cpp (Hmd2/VrTracker2, reprojection, Sense, haptics), vr_desktop.cpp (simulation).
  platform/vr_eyes.{h,cpp}: eye texture -> tiled direct-memory buffers. platform/vmath.h: Mat4/quaternion helpers.
- ps5/: build.sh (stage + build with the boilerplate), release.sh, param.json, libc_shims.c, art/ (icon, backgrounds), demo/ (synthesised song).
- tests/game_test.cpp, test/hands.cpp (controller+storage probe title), tools/ (map/view/art/demo/index/log helpers).

## data flow
mp3 -> `audio::decodeMp3` (48k stereo int16, `track`) -> `library::toAnalysisRate` (22.05k mono float) -> `analysis::analyse` (Result) ->
`mapper::generate(Result, seed)` (Song: 4 maps + beats + bars + cues) -> cached as `<id>.v<kMapperVersion>.s<seed>.pulse` ->
`game::Session(notes)` per play. Each frame: sabers[] (scene space) + song time -> `Session::update` -> events -> fx/clicks/haptics.
Render: `render::draw(vp, Scene, bg)` per eye (VR) or once (flat). Audio: thread calls `fill()`; `playPos` is the clock.

## coordinates, units, time
Scene space: metres, y up, player at origin facing -z, head rest height 1.6. Tracker space -> scene via recentre origin
(vr::origin; `toScene`/`quatToScene` in main.cpp): subtract origin, undo yaw-only rotation, +1.6 y. Quaternions are (x,y,z,w).
Note grid: lane 0..3 (x=(lane-1.5)*0.6), row 0..2 (y=1.0+row*0.55), notes fly toward +z, hit plane z=-0.8, speed 14 m/s.
Song time (s) = playPos/48000; negative during the 3 s lead-in. Never use frame time for judging.
Cut dir codes: 0 up 1 down 2 left 3 right 4 UL 5 UR 6 DL 7 DR 8 dot 9 vert 10 horiz 11 '/' 12 '\'. color 0 left/red, 1 right/blue.

## rules (per level; pinned by tests/game_test.cpp #8-#9, shown in the Help screen)
Easy dots: any dir; right-colour touch counts at any speed (touchCuts). Medium lines: along axis full, across x0.5, no combo break
for direction. Hard/Extreme arrows: direction required (cardinal within 45 deg, diagonal within 22.5 deg) else BadCut (0 pts, combo 0).
Wrong colour or too-slow swing (non-dot) = BadCut/miss on every level. Score/cut <= 115 x multiplier (1,2,4,8 at combo 0,2,6,14).
Rank: rating = 50*hitShare + 50*min(1, accuracy%/60); S>=90 A80 B70 C50 D40 E30 F. (scores.cpp, game_test #10).

## persistent files
`<STORAGE>` = `/download0/` console, `build/` desktop. settings.txt "paletteId swap bgMode"; seeds.txt "id seed"; scores.txt
"id[~seed]:diff score acc combo plays [rating]"; blade-axis.txt; cache/*.pulse. Songs: `/app0/assets/songs/**.mp3` (+ optional index.txt).
.pulse format: see mapper.cpp write()/read(). index.txt: "relative/path.mp3[<TAB>bytes]" per line.

## console hazards (all observed on hardware; do not relearn them; the full platform notes are in docs/PS5-VR2-NOTES.md)
- Title sandbox: opendir() returns EPERM for /mnt, /mnt/usb0, /data, /download0 (fopen of files works). Listing /app0 is unverified
  (the game logs "cannot list ... errno N" per dir). index.txt is the fallback. Do not rely on directory listing outside /app0.
- Heap: runtime default 128 MiB; main.cpp defines `ps5_opengl_heap_size`=1 GiB (falls back by halving). Free the previous song before
  decoding the next (loadSongEntry). Tracks > ~17 min are refused (mp3.cpp kMaxSamples). Measured: heap in use 60-143 MiB per song.
- In VR the title must NOT present flat frames (drawFlat/platform::swap): the flat bloom path crashed the console. Loading screens
  render through drawEyes. After VR starts only vr::submit presents.
- GL does not clip at the eye plane: triangles reaching behind the camera vanish. Tile big flat geometry (panel plate = 0.3 m tiles);
  cull notes with z > maxZ.
- Saber glow is additive without depth write: draw opaque UI before sabers.
- Pad: Sense controllers read via ordinary scePadReadState; right stick bytes alternate 4-5/6-7 (vr_ps5.cpp hand()). Firmware 13.60 export
  offsets only; unknown firmware => functions resolved by dlsym or the headset fails to init (flat TV view then).
- Log lines containing "error"/"failed"/"no such" pop up on the console; startup is noisy otherwise.
- Release builds compile out all network code (PULSE_RELEASE): the catalog's release scan reports "no sign of leaving the sandbox".
  Keep it that way: do not add sockets, exec, payload loading or elevation to anything shipped.

## change checklists
- mapper/analysis behaviour change => bump `library::kMapperVersion` (library.h), run `make test`, `./build/pulse-map` on a song.
- rules change => update core/game.cpp header, tests #8-#10, buildHelp text (game/main.cpp), README.
- new UI text => ASCII or Cyrillic only (atlas); lines <= ~46 chars at size .0115; rows wider than 2.4 m shrink to fit.
- new screen => add to `Screen`, a `build*`, a case in refreshPanel() and in the input switch, and `--screen` if you want a shot.
- rendering change => look at a `--shot` (desktop) AND think about the headset: no bloom there, no big slabs, mind draw order.
- every outward action (push to repo, console, catalog PR) needs the user's go. commit only when asked. identity for commits and the
  catalog account is `shwan-ps5` with the noreply address; never put private paths, addresses or credentials in the repo.

## building a NEW PS VR2 game on this base
Reuse as is: platform/ (all), vr_eyes, vmath, render's text/panel/background/bloom pieces, library/tags/scores if you have songs,
ps5/build.sh + release.sh + param.json (new titleId, contentId, titleName), tools/makeart.py for icon/backgrounds.
Minimal VR loop (see main()): platform::init -> render::init -> vr::init(platform::user()) && vr_eyes::init() -> add a depth
renderbuffer to vr_eyes::framebuffer() -> vr::start(vr_eyes::targets()) -> each frame: vr::waitSlot (console) / vr::begin(f) ->
vr::hand(0|1, h) -> your update in scene space (toScene/quatToScene) -> for each eye: glViewport(e*eye,0,eye,eye),
draw with frustum(f.eye[e].tan,0.05,150)*eyeView(pos,quat) -> glFinish -> vr_eyes::fill(f.buffer) -> vr::submit().
Pick a NEW title id (catalog: one id per app, `PPSA99xxx` range is homebrew by convention; check apps/ in the catalog repo first).
Write the rules engine like core/game.* (platform-free, unit tested) and keep per-frame work small: 60 Hz render slot, 2048x2048 per eye.
